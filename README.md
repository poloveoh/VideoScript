# VideoScript — 本地视频转文字

个人学习用途的本地原型：提取 YouTube 已有字幕，或使用本地 Whisper 模型把视频 / 音频转成可编辑的文字稿，支持 TXT 和原始 SRT 导出。

## 安装（Windows x64）

不需要预先安装 Python、Node.js 或 Git。按下面四步操作：

1. 在仓库页面点击 **Code → Download ZIP**。
2. 解压到你自己选择、且有写入权限的位置；首次安装前可以修改文件夹名称。
3. 打开包含 `Install.ps1` 的文件夹，在文件资源管理器地址栏输入 `powershell`，按 Enter。
4. 复制下面这一行，粘贴到 PowerShell 后按 Enter：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1
```

安装器会以 `Install.ps1` 所在的文件夹为安装位置，自动准备 Python、Node.js、所需组件和 Small 多语言模型，完成后启动工具。首次安装需要联网，等待安装完成即可。

**以后使用：** 在同一文件夹双击 `Start.cmd` 启动，双击 `Stop.cmd` 停止。搬迁文件夹后，按下一节执行同一行修复。

### 文件夹搬迁后，一行修复

先停止工具，再移动或改名整个项目文件夹，保留 `.tools/`、`data/` 和其他项目文件。在新位置的文件夹地址栏输入 `powershell` 并按 Enter，然后执行相同的一行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1
```

新版安装器会实际运行 Python，检查版本、当前项目路径和基础解释器路径。若 `.venv` 失效或指向旧位置，会将其改名为 `.venv.backup-<随机编号>`，然后重建环境、重装依赖并启动工具；健康环境会直接复用。失败后可以再次运行同一行，继续准备依赖。

模型和文字稿位于 `data/`，修复不会删除它们，也不会重新下载已经完整缓存的同一个模型。之前输入的本地媒体路径不会自动改写，外部文件搬迁后可能需要重新选择。旧环境备份会占用磁盘，确认工具正常后可以自行清理 `.venv.backup-*`，不要误删 `data/` 或 `.tools/`。

修复仍可能需要联网；网络、磁盘空间、Windows 文件权限或运行中的进程可能使它失败。若工具还在运行，先双击 `Stop.cmd` 再修复。该功能只存在于新版 `Install.ps1`；以前下载的 ZIP 不会自动更新，请先获取新版脚本（或下载新版 ZIP，保留自己的 `data/`）。

下载源为 Astral 官方 GitHub、nodejs.org、Python 包仓库及 Hugging Face 模型仓库。Node.js ZIP 会校验官方 SHA256。首次安装需要网络、足够磁盘空间和执行权限；学校 / 公司策略、网络限制或缺失的系统运行库可能使安装失败，脚本会报错停止。没有在所有 Windows 电脑上验证过。搬迁时请保留整个项目，并按上述步骤修复环境。

可选参数：`-SkipModel` 暂不下载模型，`-NoLaunch` 安装后不打开工具。默认只准备 Small，不会预先下载 Base、Medium 或 Large。当前界面最大选项是 Medium，首次使用才会下载；Large 不在当前界面中。

## 开始使用

1. 双击同目录的 **Start.cmd**。工具准备好后会自动打开浏览器，服务在后台运行。
2. 浏览器访问 **http://127.0.0.1:8501**。
3. 在「YouTube 链接」粘贴链接，点击「检查视频与字幕」，选择字幕后生成文字稿。
4. 没有字幕或字幕质量不好时，手动切换「本地识别音频」。也可以上传本地视频 / 音频，或输入大文件的完整路径。
5. 阅读并修改，点击「保存修改」，或者下载 TXT / 原始 SRT。

默认 Small 多语言模型；首次使用一个模型会联网下载。Tiny 适合先测试流程，Small 是质量与速度的起点，Medium 更慢。模型运行在 CPU 上，不需要 NVIDIA 显卡或付费 API。专业术语输入框只是识别提示，不能保证准确。请核对重要文字。

若启动后浏览器没有自动打开，手动访问上述地址即可。已有安装可能缓存了模型；新安装需要下载。

双击 **Stop.cmd** 可停止服务。关闭浏览器或刷新页面不会停止正在运行的转录 worker。重新打开后，从左侧历史记录选择任务并点击「打开记录」即可查看持久化进度。Windows 锁屏不会停止转录；睡眠期间 CPU 工作会暂停，唤醒后通常继续。点击「停止转录」最多等待 5 秒；若当前 Whisper 片段仍未返回，就结束后台进程并只舍弃该片段，之前保存的文字会保留。之后可以点击「继续转录」从最后保存时间点续跑。未保存的人工编辑仍不会保留。

## 本地保存

- `data/jobs/<任务编号>/job.json`：任务信息、分段和保存的编辑。
- 新任务在任务目录中保存 `影片标题.txt`（文字稿）和 `影片标题.srt`（原始识别字幕）。文件名保留中文，替换 Windows 不允许的字符并限制长度；本地媒体标题末尾的音视频扩展名会移除。不同任务仍使用独立编号目录，避免同名冲突。
- 旧任务继续使用 `transcript.txt` 和 `original.srt`，无需迁移；所有任务下载 TXT、SRT 时均使用影片标题。
- `captions.json3` / `audio.*` / `input.*`：获取的字幕或媒体。
- `data/models/`：下载的语音模型。

识别过程中逐段保存。停止、意外退出或重启后，已保存内容仍可取回，并可从最后完整片段继续。任务记录不会自动删除；关闭应用后可手动清理不再需要的任务目录。使用本地路径时原文件不被修改或删除。

新任务默认启用「成功转录后自动删除临时媒体」。程序仅在任务完成且该任务的 TXT 与 SRT 文件通过完整性验证后，删除任务目录中的上传副本或 YouTube 下载音频。验证同时兼容新任务的标题文件名与旧任务的固定文件名。暂停、停止、失败任务以及通过完整文件路径读取的原始媒体不会被删除。清理失败不会影响已完成的文字稿，可在任务页面单独重试。

TXT 使用当前编辑文字；SRT 使用原始分段文字，两者明确分开。工具只调整字幕换行和阅读段落，不自动改写、翻译、总结或推测缺失内容。

## 网络与限制

字幕提取与 YouTube 音频下载需要联网，首次模型下载也需要联网。已有模型处理本地文件时不需要网络。语音不会发送给云端转录服务；应用仅监听本机地址，未发布网站。

YouTube 可能限制请求，出现 403、429、登录或验证要求。工具不读取浏览器 Cookie，不自动绕过限制，也不保证所有视频都可下载。失败时可稍后重试，或使用你已有的本地文件。手动入口仍处理单个视频；Playlist MVP 入口见下节。不支持直播中的视频。手动字幕失败后不会自动启动耗时的音频识别。

## Playlist 自动同步 MVP

在「Playlist 管理」添加有效的 YouTube Playlist URL。重复添加会重新启用原记录；停用或勾选确认后移除均保留已保存的文字稿。Sync Now 只向托盘发送后台请求；普通页面刷新不会联网同步。界面显示状态、最近错误、视频数、最近 20 条发现和只读 FIFO 队列。

Start.cmd 启动一个本机网页服务及一个隐藏窗口的托盘伴随程序；重复启动不会增加副本。托盘每 10 分钟同步已启用的 Playlist，按发现顺序串行处理，跨 Playlist 的同一视频共用任务。自动处理优先提取原语言字幕（同语言优先创作者字幕，其次自动字幕）；没有可用字幕或提取失败时使用 Medium 本地识别，首次模型使用需要下载。失败或中断最多自动重试一次，不保证 YouTube 可访问。

托盘菜单：Open VideoScript、Sync Now、Pause / Resume Auto Sync、Exit。暂停只停止周期同步；Sync Now 仍可手动请求，既有队列仍会处理。Exit / Stop.cmd 会请求队列安全退出并停止网页服务；关闭浏览器不会停止后台处理。手动 1.0 转录 worker 仍按原有界面单独停止 / 继续。

`data/videoscript.db` 保存 Playlist、成员关系、视频身份和 FIFO 状态；`data/jobs/` 保存文字稿。`data/sync.requested` 是合并同步请求标记；`data/server.pid`、`data/tray.pid` 是带进程身份的 JSON 元数据，不能只当作整数 PID。停止和重启不会删除数据库或文字稿。应用只监听 `127.0.0.1:8501`，无自动开机功能。

托盘未出现时，可直接访问网页和 `http://127.0.0.1:8501/_stcore/health`，查看 `data/tray-error.log`、`data/server-error.log`。缺少 pystray 时按安装步骤补齐锁定依赖。托盘启动失败会保留网页用于诊断；此时页面的同步请求等待托盘恢复。修复后重新运行 Start.cmd。若端口属于未验证的旧服务，Start 会拒绝接管；先从该安装目录正常停止它。过期 PID 元数据不会用于停止其他进程。Stop 若等待托盘超过 30 秒会报告错误并保留现场；检查日志后再重试，不要按 PID 手动结束未知进程。

**限流不是固定时段。** 429 可能与一段时间内的请求频率、出口 IP / 会话及所请求的字幕接口有关；部分自动翻译字幕也有已知 429 问题。暂停请求后可能恢复，但没有保证的等待分钟数或「晚上一定能用」规则。不要连续点击重试；可优先选原语言字幕，或使用已有本地音视频。当前工具没有实现自动限流冷却；Playlist 队列的有限失败重试不保证解除限流。参考 [yt-dlp FAQ](https://github.com/yt-dlp/yt-dlp/wiki/FAQ) 和 [字幕 429 问题记录](https://github.com/yt-dlp/yt-dlp/issues/13831)。

`WinError 10013` 则表示连接被本机权限 / 安全策略阻止，不等同于 YouTube 429；应检查运行环境的联网许可，不能只靠等待。通常建议从 Windows 双击 `Start.cmd` 启动，避免继承受限代理环境。

## 环境与维护

运行环境保存在项目内的 `.tools/` 和 `.venv/`。FFmpeg、yt-dlp/EJS 和 Python 依赖由安装器统一准备，不需要逐项安装。依赖版本记录在 `requirements.lock.txt`。

安装、补齐依赖和搬迁修复均使用本页开头的同一条 `Install.ps1` 指令。旧 ZIP 不会自动更新；需要新版功能时，请先获取新版项目文件并保留自己的 `data/`。

YouTube 行为变化时，可能需要单独更新 yt-dlp。在项目目录使用安装器附带的 uv：

```powershell
.\.tools\uv\uv.exe pip install --python .\.venv\Scripts\python.exe --upgrade "yt-dlp[default]"
```
